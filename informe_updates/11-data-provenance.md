# Data provenance: what is real, what is synthesized, what is scripted

- **Dataset:** Wiefling, Jørgensen, Thunem, Lo Iacono, *Login Data Set for
  Risk-Based Authentication*, Zenodo, DOI 10.5281/zenodo.6782156 (paper: ACM
  TOPS 2022, DOI 10.1145/3546069). Derived from >33M real login attempts of
  3.3M users of a Norwegian SSO service (Feb 2020–Feb 2021), synthesized by the
  authors for privacy: statistical relations kept (per-user and global value
  frequencies, order, attack / takeover labels), concrete values replaced
  (country → ASN → IP reassigned, OS / browser names reassigned, timestamps with
  noise). The authors verified it reproduces their study's results with the
  Freeman model. Not generated by an LLM; a documented, peer-reviewed procedure.
- **Scripted by us (no LLM-generated data):** simulated attackers for the
  evaluation (`ml/attacker_eval.py`, Wiefling's attacker definitions, seeded
  RNG over the dataset's own attack IPs); local demo history (`seed.py`, fixed
  loop); load-test requests; demo users and tenants (code fixtures).
- **Every number in the findings** comes from running those scripts on the
  dataset; each finding lists its reproduction command.
- **Review:** the data section (describe origin and synthesis as above), the
  limitations (value names do not transfer, hence ADR-0043), the evaluation
  method (simulated attackers named as simulation), and, if the informe
  mentions AI assistance: AI helped write code; data and results come from the
  dataset and deterministic scripts.
